# 60. 多言語の全数調査 — 日本語画面に韓国語・英語を残さない

**日本語** | [한국어](60-i18n-audit.ko.md)

> 背景: ホームで日本語に切り替えてもメッセージが韓国語で出る、あるいは画面に韓国語・英語が残っていた。→ ホームだけでなく**全画面**を調査して直す。

## 1. 何が残っていたか — 三系統

| 系統 | 規模(調査時点) | なぜ生じたか |
|---|---|---|
| **画面に埋め込まれた文言** — JSX テキスト、placeholder・title・alt、トースト・エラー文言、状態ラベル | 118 ファイル、**1,091 箇所**(管理者 約 480) | 辞書(i18n/messages)はあったが、ログイン・カートのサマリーなど一部の画面しか移行されていなかった。韓国語画面では正しい文字なので、レビューでは目に入らない |
| **サーバーが送る文言** — エラー・案内(`{"message": "장바구니가 비어 있습니다…"}`) | 9 サービス、**約 290 個** | サーバーの文言がすべて韓国語でコードに埋め込まれており、画面は受け取った文言をそのまま表示する。リクエストに言語情報もなかった |
| **ゲートウェイの文言** — ログインが必要(401)、サービス利用不可・タイムアウト(フォールバック) | 5 個 | ゲートウェイが直接作る(WebFlux) |

## 2. 画面 — 辞書へ

- 辞書を**領域別のファイル**に分けた(`i18n/messages/areas/{shell,shop,order,user,admin1,admin2}.{ko,ja}.js`、`ko.js`・`ja.js` がまとめる)。
  一つのファイルに集めると、複数人が同時に修正するときに常に衝突する。同じキーが二つの断片にあると `i18n.test.jsx` が失敗する(後のものが
  黙って上書きする)。
- コンポーネント内は `useTranslation().t`、外(ユーティリティ・トースト・API ラッパー・モジュールレベルの関数)は `translate()` — 呼び出した**その瞬間**の言語である。
  モジュールレベルの定数(決済手段リスト、状態ラベル、ソートオプション)は**キーを持ち**、描画時に翻訳する — 定数はインポート時に一度だけ計算されるので、
  文言を入れると言語を切り替えてもそのままになる。
- サーバーへ送る値(ソート値、状態コード、フィット値 "Small"・"True to size")はそのままにして、**表示するときだけ**翻訳する。

## 3. `translate()` — コンポーネント外の翻訳

`I18nProvider` が現在の言語をモジュール変数としても保持している(レンダリング中に合わせる — 子の初回レンダリング・初回リクエストからその言語でなければならない)。
`translate(key, vars)` はその言語で、`getCurrentLang()` は言語コードを返す。

## 4. サーバーの文言 — リクエストの言語で

### リクエスト

画面のすべての API リクエストに `Accept-Language: <화면 언어>` (`util/api.js` のインターセプター)。Spring はこれでリクエストのロケールを決める。

### レスポンス — `ClientText` + `ClientTextResponseAdvice`(common)

サーバーの文言をメッセージキーに置き換えはしなかった — 250 個をキーに置き換えると、ログ・テスト・運用ドキュメントがすべてキーになり、韓国語の運用者がログを
読めなくなる。代わりに**韓国語の原文がキー**であるカタログ(gettext 方式)で、**レスポンスとして出ていく瞬間に**置き換える。韓国語のリクエストでは何もしない。

```
# <モジュール>/src/main/resources/i18n/client-text.ja.txt
장바구니가 비어 있습니다. 상품을 담은 뒤 다시 시도해 주세요.
= カートが空です。商品を追加してからもう一度お試しください。

재고가 부족해 주문하지 못했습니다: {}. 장바구니에서 수량을 조정해 주세요.
= 在庫が不足しているため注文できませんでした：{}。カートで数量を調整してください。

{}({}) 품절
= {}（{}）売り切れ
```

| 決定 | 理由 |
|---|---|
| `{}` = 連結された部分、翻訳は `{}` または `{0}`・`{1}`(順序の入れ替え) | 文字列を連結した文言が多い(`"주문 " + id + "을 찾을 수 없습니다"`) |
| 変わる部分も再度カタログで探す、カンマ区切りのリストは断片ごとに | 「티셔츠(M) 남은 수량 1개, 바지(L) 품절」 — リスト内の断片も翻訳されなければならない。商品名はそのまま |
| `= -` は運用者向け | 起動設定の検証・Kafka シリアライズ失敗のように、お客様に届かない文言。入れ忘れたものと意図的に残したものを区別する |
| 置き換える場所は**レスポンスの封筒だけ** — 文字列本文、マップの `message·error·detail·reason`、`MessageResponse·ApiError·ApiResponse·ErrorMessage·GenericResponse·CouponResponse·LoginResponse` | `message` というフィールドはチャットメッセージ・通知本文のように人が書いた文章にもある。カタログのパターンに偶然一致するとユーザーの文章が変わってしまう |
| リクエスト外(Kafka リスナー・スケジューラー)では置き換えない | その文言はレスポンスではない |
| 自動構成で適用する | common をコンポーネントスキャンしないサービス(catalog・user・coupon…)も受け取れる。スキャンするサービスで二重に適用されることはない |

### ガード — `ClientTextCoverageTest`(common)

各サービスのソースから**レスポンスとして出ていきうる箇所**(例外のコンストラクタ、レスポンスの封筒、`.body(…)`、`Map.of("message"|"error", …)`、検証
アノテーションの `message=`、`ClientMessage.of` の代替文言、`ErrorCode` の説明)の韓国語文言を抽出し、カタログと突き合わせる。抜けているものは
`common/build/client-text-missing/<모듈>.txt` に**カタログの形そのままで**書き出される — 翻訳を埋めるだけでよい。ヘルパーメソッドが作って
変数として渡す文言(在庫不足リストなど)は抽出されないので、パターンとして直接書いた。

### ゲートウェイ

WebFlux で文言が五つしかないので、`GatewayText.pick(exchange, ko, ja)` で両方を持って選ぶ。

## 5. ガード — `hardcodedText.test.js`(画面)

ソースを**構文木**として読み、画面に見えるハードコードされた文言を探す: JSX テキストのハングル・英語、見える属性(placeholder・title・alt・
aria-label・label)、ハングルを含む文字列・テンプレート(console.* の引数は除外)、トースト・alert・confirm・setError・Error に渡す英語の文、
オブジェクトの label・title・description・message 属性の英語の文。見逃すものは `hardcodedText.allow.js` にだけ — 商標・通貨記号のように
翻訳しないのが正しい文字だけである。一部だけ見るには `I18N_SCAN_ONLY=pages/admin,components/admin`。

## 7. 残っていること — 正直に

- 解決したもの: チャットのシステムメッセージ(§8)、通知本文(§9)、配送シミュレーターの履歴文言・配送業者名(§10)、国リスト(§11)、
  PortOne のエラー文言(§12)、韓国郵便(Korea Post)の状態語・カンマを含む商品名のリスト(§13)。
- **韓国郵便(Korea Post)の履歴の場所**(郵便局・集中局の名前)は固有名詞なので原文のまま出る。状態語以外の自由記述の文言も同様である。
- **商品・カテゴリ名、ユーザーが書いたレビュー**はデータなので翻訳しない。
- **メール・SMS** はすでに受信者の言語で二組を持っている(MailTemplates・SmsTemplates)。

## 8. チャットのシステムメッセージ

入室・退室の案内(`"홍길동 entered."`・`"… leaved."` — 英語)、オペレーターの接続・終了案内(「상담원 ○○ 님이 연결되었습니다」、「고객님이 상담을
종료했습니다」)、代替名(「고객지원팀」・「탈퇴한 사용자」・「회원」・「회원 3f2k」)は、サーバーが**文言そのまま**メッセージ本文・ニックネームとして保存する
(Kafka Avro `ChatMessage` → Mongo)。

| 決定 | 理由 |
|---|---|
| メッセージにコード・引数のフィールドを追加せず、画面が**サーバーの決まった形を認識して**辞書で描き直す(`util/chatNotice.js`) | フィールドを追加するには Avro スキーマを二つのリリースにまたがって変更する必要があり(docs/55)、それでも**すでに保存された**メッセージは文言だけである。形はサーバーが作ったものなので認識できる — 古いメッセージまで翻訳される |
| サーバーの文言を一箇所(`ChatNotices`)に集め、画面の `SERVER_FORMATS` と文字で照合(`ChatNoticesContractTest`) | サーバーの文言を変えて画面を忘れると、日本語画面に韓国語がそのまま出る — 韓国語画面では正常に見える |
| 🔒 **案内の箇所でだけ**翻訳する(メッセージ種別 TEXT_ENTER・TEXT_LEAVE、ニックネーム・相談リストの名前・プレビュー) | 人が書いたチャットが偶然同じ文でも置き換えない |
| 案内の中の名前も再度探す | 「탈퇴한 사용자 entered.」 → 「退会したユーザーさんが入室しました。」 |
| "leaved" は誤った英語だがそのまま | 保存されたメッセージがこの形である。画面が翻訳するので、お客様には見えない |

適用した箇所: 友達チャットの吹き出し・新着メッセージ通知、相談会話の案内・送信者名、相談デスクのリスト(顧客・オペレーター名、最後のメッセージの
プレビュー)・新着メッセージのトースト、顧客の相談画面のオペレーター名。

## 9. 通知本文

決済・注文・配送・クーポン・セキュリティ・購入確定・部分返金・再入荷・チャット・相談回答・友達のログイン通知は、notification-service が**韓国語の文言で
作って DB に保存**する(タイトル・本文)。通知ベルのリストはその文言をそのまま表示していた。

| 決定 | 理由 |
|---|---|
| 保存は韓国語のまま、**リストを返すときに**リクエストの言語に置き換える(`NotificationResponse.localized` → `ClientText`) | 受信者は画面の言語をいつでも切り替える。保存時に翻訳するとその瞬間の言語で固まる — 読むときに選べば**すでに溜まった通知も**一緒に変わる。DB の変更もない |
| 文言を一箇所(`NotificationTexts`)に集め、形のリスト(`FORMATS`)を置く | リスナーのあちこちに散らばっていた(配送状態別のタイトル・本文、セキュリティ本文など)。形ごとに例の値を入れて日本語に変わるかを見る `NotificationTextsTest` — 新しい文言を追加してカタログを忘れると失敗する |
| 変わる箇所(注文番号・クーポン名・商品名・金額・デバイス)はそのまま | データである。ただし「알 수 없는 브라우저」(user-service のデバイス名の代替値)は翻訳する |
| 全体通知(お知らせ)は翻訳しない | 管理者が書いた文章である |
| メール・SMS のタイトルも | メール・SMS にはすでに受信地域(KR/JP)別のテンプレートがあったが、テンプレートに差し込むタイトル(「주문 123」)が韓国語だった — 日本地域なら差し込む前に置き換える |

通知ベルは開くたびにリストを新たに受け取るので、言語を切り替えた後に開けばすぐにその言語になる。

## 10. 配送履歴(シミュレーター)・配送業者名

テスト配送(`SimulatedCarrierAdapter`)は履歴ごとに場所(「대전허브」)・説明(「이동 중입니다」)を**韓国語で保存**し、配送照会画面は
その文字をそのまま描いていた。配送業者名も `carrier.name_ko` のままだった。

| 決定 | 理由 |
|---|---|
| 保存は韓国語のまま、**照会レスポンスを作るときに**(`DeliveryResponse`) `ClientText` で置き換える | 場所は履歴の重複排除キー(`DeliveryEvent.dedupKey`)の一部である — 言語別に保存すると同じイベントが二度溜まる。読むときに置き換えれば、すでに溜まった履歴も変わる(§9 と同じ方式) |
| 文言を `SimulatedCarrierTexts` に集め、リスト(`FORMATS`)を置く | `SimulatedCarrierTextsTest` がすべての場所・説明・配送業者名の日本語を、配送業者が作るすべての状態の説明を、照会レスポンスの翻訳と保存値の不変を確認する |
| 配送業者名(「우체국택배」・「테스트배송」・「CJ대한통운」など、V3 シード)も同じカタログで | 新しいカラム(`name_ja`)は作らない — 配送業者はシードの五つだけである |
| 実際の配送業者の文言はカタログに入れない | 配送業者が送ってきたデータである。カタログになければ原文のまま出る — 段階(stage)は画面がすでに辞書で描いている |

配送照会・管理者の配送画面はいずれもこのレスポンスを使い、リクエストごとに `Accept-Language` が付くので、フロントの変更はない。

## 11. 国リスト — コードで保存、名前は描画時に

住所フォームの国選択は英語名(「Korea, Republic of」)を**値として**保存していた。そのため日本語画面でもリスト・住所カード・注文詳細が
英語で、名前を翻訳すると保存値が言語ごとに変わってしまう。

| 決定 | 理由 |
|---|---|
| 新たに保存する値は **ISO alpha-2 コード**(「KR」)、デフォルト値も `KR` | 言語と無関係な値。配送(delivery-service `CountryCodes`)はもともと名前・コードをすべて alpha-2 に変換して保存するので、サーバーの変更はない |
| 名前はブラウザの `Intl.DisplayNames`(CLDR)で — `util/country.js` | 250 か国の名前を辞書に書き写さない。ない環境ならリストの英語名で |
| 選択肢はその言語の名前の順(`Intl.Collator`) | 日本語の名前を英語のアルファベット順に並べると見つけられない |
| **古い住所(英語名)も読む** — `toCountryCode` が名前・コードをすべてコードに | すでに保存された住所・注文は変えない(DB 変更なし)。修正フォームに入れるときにコードに変換するので欄が空に見えず、保存するとコードになる |
| リストにない値はそのまま表示される | 人が直接入力した値かもしれない |

適用した箇所: 住所入力(選択肢)、配送先カード、注文詳細の配送・請求先住所、管理者の配送画面(配送の国はコードである)。
テスト: `util/country.test.js`(すべての国の日本語名・古い名前の読み取り・ソート)、`AddShipping`(古い住所の修正 → コードで保存、日本語リスト)、
`ListShipping`(日本語カード)。

## 12. PortOne のエラー文言

PortOne は決済ウィンドウが失敗すると **PG が書いた文言**をそのまま渡す — V1 `error_msg`(「[결제포기] 사용자가 결제를 취소하셨습니다」)、
V2 `message`・`code`。国内 PG なのでたいてい韓国語で、こちらでは選べない。画面はその文字をそのまま表示していた。

| 決定 | 理由 |
|---|---|
| **何が起きたかを認識して**辞書の文言で言い直す(`util/portoneError.js`) — キャンセル・タイムアウト・残高/限度額・カード情報・本人認証 | PG は同じことを様々な形で書く。最もよくある失敗(ユーザーのキャンセル)から順に見る |
| 認識できなかった文言: 韓国語画面は**原文のまま**、他の言語は一般的な案内 + **エラーコードのみ** | 原文が原因を最もよく語るが、日本語のお客様は読めない。コードはカスタマーサポートが調べる手がかりとして残し、原文はコンソールに |
| サーバーレスポンス内の PortOne の原文(`message={}`・`— {}`)は日本語訳から**除く**(order-service のカタログ) | 照会・返金拒否の後半部分は PortOne が書いた韓国語である。日本語にはコード・決済 id だけを残す — 原文はサーバーログにある |

テスト: `util/portoneError.test.js`(種別判定 8 通り、日本語にハングルが残らない、コードだけ付ける、韓国語は原文)、
`OrderClientTextTest.portOneProviderTextIsDropped`.

## 13. 韓国郵便(Korea Post)の状態語 · カンマを含む商品名

| 何を | 前 | 後 |
|---|---|---|
| 実際の配送業者(韓国郵便)の履歴の説明 | 配送業者が送ってきた韓国語のまま | 状態語は決まった数個である — アダプターが状態を認識するのに使う語(`KoreaPostCarrierAdapter.STATUS_RULES`)すべてとよくある変形(집하・집하완료)を delivery カタログに。「배달완료(홍길동)」は `배달완료({})` に — 受取人の名前はそのまま。場所の名前は固有名詞なのでそのまま |
| 在庫不足リスト「셔츠, 블루(M) 품절, 바지(L) 남은 수량 1개」 | 「, 」で切って断片ごとに翻訳 — 名前の途中で切れて「셔츠」・「블루(M) 품절」のどちらも形に合わず、**原文のまま**出ていた | 合う形が出るまで**隣の断片をつなげる**(最も短いもの) — 「셔츠, 블루（M）売り切れ、바지（L）残り1点」 |

テスト: `SimulatedCarrierTextsTest.koreaPostStatusWords`(アダプターの状態語をリフレクションで読んで全部 — アダプターに語を追加して
カタログを忘れると失敗)、`ClientTextTest.listWithCommaInsideName`.

## 14. 日本語入力の全角 · 半角 — 検索 · 識別用の値だけ NFKC (2026-10-24)

日本語 IME は全角英数(`ＴＳＨＩＲＴ` · `１２３`) · 半角カナ(`ｼｬﾂ`) · 全角スペースを出しやすい。以前はどこも正規化しておらず、以下がすべて失敗していた。

| 入力 | 以前 | 今 |
|---|---|---|
| 商品検索 `ｼｬﾂ` · `ＴシャツＢＡＳＩＣ` | `lower(name) LIKE` — 文字が違い 0 件 | 検索語は受け取り時に NFKC(`SearchParamsRequest.setSearch` — キャッシュキー · ES · DB が同じ文字)、名前は原文のまま比較にだけ DB 関数 `product.search_key`(`lower(normalize(…, NFKC))`、catalog V23)を両側に — 式インデックス `idx_product_name_search_key_trgm` |

- **表示する文には使わない。** NFKC は文字を変える — `① → 1`、`㈱ → (株)`、`ﬁ → fi`。名前 · 住所 · レビュー · チャット · 商品名(表示)は原文。
- 共通の道具: `common.text.Nfkc`(`of` = NFKC + 前後の空白、`searchKey` = さらに連続空白を一つに)。画面は `util/searchKey.js`。
